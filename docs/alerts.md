# 알림 사전

> 읽는 사람: 현업 · 전산팀

카드 제목의 「무슨 일」 자리에 오는 이름을 풀어 둔 표입니다.

- **먼저 볼 사람**은 카드의 「담당」과 같습니다.
- 기준은 지금 설정값입니다. 바뀌면 이 쪽도 같이 고칩니다.

## 낱말 풀이

| 낱말 | 뜻 |
| --- | --- |
| 오류 응답(5xx) | 서버가 요청에 「처리 실패」로 답한 것 |
| 백엔드 | 화면 뒤에서 사내 DB 를 읽고 쓰는 공용 서버 |
| 재시작 | 서버 프로그램이 꺼졌다 다시 켜진 것 |
| 로그 | 앱이 일하면서 남기는 기록 한 줄 |
| 정기 작업 | 사람이 누르지 않아도 정해진 시간에 도는 작업 |

## 앱 공통

모든 앱에 걸려 있습니다.

| 알림 | 쉬운 뜻 | 언제 울리나 | 등급 | 먼저 볼 사람 | 할 일 |
| --- | --- | --- | --- | --- | --- |
| 오류 응답 발생 | 화면 요청이 실패로 끝나고 있음 | 15분 동안 5건 초과 | 주의 | 앱 담당 팀 | 화면 접속 확인 → 복구 알림이 없으면 원인 확인, 앱 문제면 이슈 등록 |
| 서버 재시작 반복 | 서버가 꺼졌다 켜지기를 되풀이 | 15분 동안 2회 초과 | 긴급 | 앱 담당 팀 | 화면 접속 확인 → 최근 배포 확인 |
| 서버 내려감 | 떠 있어야 할 서버가 0대 | 5분 평균 1대 미만 (항상 켜 두는 앱만) | 긴급 | 앱 담당 팀 | 접속 확인 → 즉시 확인, 전산팀 연락 |
| 메모리 부족 임박 | 메모리가 거의 다 참 | 15분 평균 85% 초과 | 주의 | 앱 담당 팀 | 무거운 기능(큰 파일 · 긴 조회) 확인 → 지속되면 전산팀에 메모리 상향 요청 |
| 메모리 부족 종료 의심 | 메모리가 모자라 서버가 꺼진 흔적 | 1시간 안에 흔적 감지 | 주의 | 앱 담당 팀 | 그 시각의 무거운 기능 확인 → 반복되면 메모리 상향 요청 |
| 백엔드 응답 없음 | 앱이 백엔드 · 사내 API 에서 답을 못 받음 | 10분 동안 5건 이상 | 주의 | 앱 담당 팀 → 전산팀 | 1~2분 뒤 재시도 → 복구 알림이 없으면 전산팀 연락 |
| 로그인 장애 의심 | 로그인 · 로그인 유지가 실패 | 10분 동안 5건 이상 | 긴급 | 전산팀 | 새 창에서 로그인 시도 → 실패하면 전산팀 즉시 연락 |
| DB 연결 실패 | 앱이 DB 에 붙지 못함 (DB 를 직접 쓰는 앱만) | 10분 동안 3건 이상 | 긴급 | 전산팀 | 전산팀 즉시 연락 |

- 「백엔드 응답 없음」 · 「로그인 장애 의심」 · 「DB 연결 실패」는 앱이 실패를 로그로 남겨야 걸 수 있습니다. 로그가 없는 앱에는 [「로그 부족」 안내](cards.md)가 갑니다.

## 정기 작업 · 워커

정해진 시간에 도는 작업이 있는 앱에 걸려 있습니다. **멈춰도 오류가 안 나는 종류**라 따로 봅니다.

| 알림 | 쉬운 뜻 | 언제 울리나 | 등급 | 먼저 볼 사람 | 할 일 |
| --- | --- | --- | --- | --- | --- |
| 작업 멈춤 의심 | 주기적으로 남아야 할 「성공」 기록이 끊김 | 2시간 동안 기록 없음 | 긴급(운항 메일 수집) · 참고(자금 뉴스 수집) | 앱 담당 팀 | 관리 화면에서 일시정지 여부 확인 → 일시정지가 아니면 전산팀 즉시 연락 |
| 정기 작업 실패 | 작업이 실패로 끝남 | 연속 실패 (운항 메일 수집: 2시간 안에 연달아 2번) | 주의 · 긴급(데이터 적재 작업) | 앱 담당 팀 | 실행 기록에서 실패 사유 확인 → 권한 · DB 문제면 전산팀 연락 |
| 정기 작업 미실행 | 돌아야 할 작업이 돌지 않음 | 마지막 실행 뒤 26시간 초과 (매일 한 번 도는 작업) | 주의 | 작업 담당 | 스케줄 · 최근 실행 기록 확인 |
| 설정 · 권한 대기 | 작업은 성공하지만 일부 대상을 건너뜀 | 1시간 안에 1건 이상 | 참고 | 앱 담당 팀 | 관리 화면에서 대상 설정(폴더 · 사서함 권한) 확인 |
| 내부 정기 작업 오류 | 앱 안에서 도는 자동 작업에 오류 | 1시간 안에 1건 이상 | 주의 | 앱 담당 팀 | 원인 확인 |
| 저장 자료 읽기 · 쓰기 실패 | 앱이 자기 설정 · 메모 파일을 못 읽거나 못 씀 | 1건 이상 | 긴급 | 전산팀 | 전산팀 즉시 연락 |
| DB 접속 토큰 갱신 실패 | DB 에 붙을 때 쓰는 출입증 갱신이 실패 | 1건 이상 | 긴급 | 전산팀 | 전산팀 즉시 연락 |

- 자금 뉴스 수집의 「작업 멈춤 의심」은 평일 업무 시간에만 봅니다. **공휴일에는 잘못 울릴 수 있습니다.**
- GitHub 이 돌리는 예약 작업은 여기가 아니라 [배포 · 예약 작업 실패 카드](cards.md)로 옵니다.

## 공통 플랫폼

여러 앱이 같이 쓰는 것들입니다. 전산팀 채널로 가고 담당은 전산팀입니다.
긴급이면 영향받는 앱의 팀 채널에도 갑니다 — **그 팀이 할 일은 없고**, 「우리 앱이 왜 안 되는지」 알라는 뜻입니다.

| 알림 | 쉬운 뜻 | 언제 울리나 | 등급 |
| --- | --- | --- | --- |
| 사내 Oracle 연결 실패 | 백엔드 · 로그인 서버가 사내 DB 에 붙지 못함 | 5분 동안 5건 이상 | 긴급 |
| VPN 단절 의심 | Azure 와 사내망을 잇는 통로가 끊긴 듯함 | 5분 평균 유입 트래픽이 거의 0 | 긴급 |
| 공용 DB 응답 없음 | 자금 · 기획 · 운항 앱이 쓰는 DB 가 답하지 않음 | 생존 신호 끊김 | 긴급 |
| 공용 DB 접속 자리 부족 | 동시에 붙을 수 있는 자리가 거의 참 | 동시 접속 40개 이상 (최대 50) | 주의 |
| 공용 DB 저장공간 부족 | 디스크가 차 감 | 사용률 80% 초과 | 주의 |
| 공용 DB 메모리 높음 | DB 메모리가 계속 높음 | 30분 평균 90% 초과 | 주의 |
| 공용 DB 과부하 | DB 가 바쁨 | 15분 평균 CPU 80% 초과 | 주의 |
| 열쇠 보관소 불안정 | 로그인에 쓰는 열쇠 보관소가 불안정 | 가용성 99% 미만 | 긴급 |
| 외부 통신 출구(NAT) 불안정 | 앱이 바깥 서비스를 부르는 출구가 불안정 | 가용성 99% 미만 | 긴급 |
| 파일 저장소(Blob) 불안정 | 파일 올리기 · 내려받기 저장소가 불안정 | 15분 평균 가용성 90% 미만 | 주의 |
