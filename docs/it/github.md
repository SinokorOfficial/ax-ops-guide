# GitHub 운영

> 읽는 사람: 전산팀

## 역할

| 무엇 | 현업이 하는 것 | 전산팀이 하는 것 | 요청 방법 |
| --- | --- | --- | --- |
| 조직 설정 · 보안 | — | 전체 통제 (조직 소유자) | — |
| 팀 · 멤버 | 팀 리더가 자기 팀원 관리 | 팀 생성 · 멤버 초대 · 권한 | 이슈 |
| 저장소 | 만들고 자기 팀에 연결 | 이관 · 삭제 · 설정 · 비밀 | 이슈 |
| 배포 세팅 | — | 인증 연결 · 저장소 변수 | 이슈 「전산팀에 부탁」 |
| 이슈 회신 | 확인 · 닫기 | 접수 · 처리 · 통지문 | — |

## 네 가지 원칙

| 원칙 | 내용 |
| --- | --- |
| 회사 소유 | 저장소는 조직에 둠. 개인 계정에 두지 않음 |
| 팀은 자기 것만 | 기본 권한 없음 — 팀에 연결된 저장소만 보임 |
| 비공개 기본 | 내부 코드는 비공개. 공개가 맞는 것(문서 · 샘플)만 공개 |
| 비밀은 저장소 밖 | 배포 인증은 비밀번호 없는 방식, 비밀은 저장소에 두지 않음 |

## 절차 체크리스트

**새 저장소**

- [ ] 저장소 생성 (비공개 기본)
- [ ] 담당 팀에 연결 (쓰기)
- [ ] 배포가 필요하면 배포 세팅
- [ ] 이슈 양식 · 라벨 · 협업 알림 연결
- [ ] 모니터링 등록 ([체크리스트](new-app-checklist.md))

**새 팀 · 새 멤버**

- [ ] 팀 생성 (이름 · 설명)
- [ ] 계정 초대 — 아이디를 모르면 회사 메일로 초대 (이름으로 추측하지 않음)
- [ ] 팀 리더 지정
- [ ] Teams 채널 연결

**이관 · 삭제 · 퇴사**

- [ ] 이관: 히스토리 비밀 점검 → 팀 연결 → 배포 인증 다시 연결
- [ ] 삭제: 2인 승인 → 기록
- [ ] 퇴사 · 이동: 접근 즉시 차단 → 비밀 교체

## 보안 기준

- [ ] 2단계 인증 필수
- [ ] 비밀 · 직원 자료 파일을 저장소에 올리지 않음
- [ ] 최소 권한 — 필요한 팀 · 수준만
- [ ] 외부 협업자는 기간 한정

## 모니터링과 이어지는 곳

| 무엇 | 동작 |
| --- | --- |
| 조직 웹훅 | 모든 저장소의 실행 결과를 받아 main 가지 실패만 팀 채널 카드로 |
| 저장소 → 채널 | 저장소 이름으로 앱과 채널을 찾음. 새 저장소는 등록해야 카드가 감 |

정본: 조직의 GitHub 거버넌스 문서, 각 앱 저장소의 「협업 방식」
