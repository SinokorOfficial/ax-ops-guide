# Azure 운영

> 읽는 사람: 전산팀

## 역할

| 무엇 | 현업이 하는 것 | 전산팀이 하는 것 | 요청 방법 |
| --- | --- | --- | --- |
| 자원 생성 · 이름 | — | 표준 이름 규칙대로 생성 | 이슈 「전산팀에 부탁」 |
| 배포 길 | main 에 합침 | 비밀번호 없는 인증 연결 · 저장소 변수 | 이슈 |
| 설정 값 · 비밀 | 필요한 값 요청 | 입력 · 보관 · 교체 | 이슈 |
| 메모리 · 서버 대수 | 부족하면 알림 | 조정 | 이슈 |
| 파일 저장소 | 화면에서 사용 | 저장 칸 · 권한 · 창구 | 이슈 「DB 요청」 |
| 사내망 연결 | — | 운영 | — |
| 비용 · 태그 | — | 관리 | — |

## 앱 하나를 올릴 때

- [ ] 표준 이름 규칙으로 자원 생성
- [ ] 태그 (과제 · 앱 · 환경 · 담당 팀)
- [ ] 배포 인증 연결 (비밀번호 없는 방식)
- [ ] 저장소 변수 입력 — 없으면 「검증까지만」 하고 배포되지 않음
- [ ] 설정 값 입력 (비밀은 보관소 참조)
- [ ] 로그인 등록
- [ ] 접속 제한 확인
- [ ] 첫 배포 뒤 상태 확인 주소 응답 확인
- [ ] 모니터링 등록 ([체크리스트](new-app-checklist.md))

## 파일 저장 원칙

| 원칙 | 내용 |
| --- | --- |
| 계정은 하나, 앱은 칸으로 | 앱마다 저장 칸을 나눔 |
| 열쇠 없이 | 앱 · 백엔드는 자기 신원으로 접근. 공유 링크 · 키를 쓰지 않음 |
| 브라우저 직접 접근 없음 | 올리기 · 내려받기는 서버를 거침 |
| 접근 판단은 앱이 | 누가 그 파일을 볼 수 있는지 매번 앱이 판단 |

## 자주 오는 요청

| 요청 | 처리 |
| --- | --- |
| 메모리 상향 | 「메모리 부족 임박」 · 「메모리 부족 종료 의심」 알림 이력 확인 뒤 조정 |
| 항상 켜 두기 | 최소 서버 대수 1 — 「서버 내려감」 알림도 같이 등록 |
| 설정 값 추가 | 비밀이면 보관소에, 아니면 직접 입력 |
| 접속 제한 변경 | 허용 범위 수정 |
