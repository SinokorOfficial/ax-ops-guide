# 운영 메모

> 읽는 사람: 전산팀

자원 이름 · 스크립트 위치 · 접속 정보는 여기 적지 않습니다 — **전산팀 내부 문서**를 봅니다.

## 고치는 순서

| 하려는 것 | 순서 |
| --- | --- |
| 카드 문구 · 채널 · 담당 변경 | 정본 스크립트의 앱 · 종류 사전 수정 → 카드 자동화 다시 배포 → 테스트 카드 |
| 알림 기준 변경 | 정본 스크립트의 규칙 수정 → 규칙 다시 등록 |
| 새 알림 종류 | 종류 사전에 문구 추가 → 규칙 등록(이름 끝을 그 종류로) → 테스트 카드 |
| 새 앱 | [새 앱 등록 체크리스트](new-app-checklist.md) |

- 포털에서 손으로 고치지 않습니다. 정본 스크립트와 어긋납니다.
- 고친 뒤 이 문서의 표(알림 사전 · 채널)도 같이 고칩니다.

## 테스트 카드

- 알림과 같은 모양의 시험 요청에 「테스트」 표시를 붙여 보냅니다.
- 테스트 카드는 앱 채널에만 가고, 긴급 사본은 가지 않습니다.

## 비용 (추정)

| 항목 | 월 |
| --- | --- |
| 지표 규칙 | 규칙당 소액 |
| 로그 규칙 | 규칙당 소액 — 확인 주기가 짧을수록 비쌈 |
| 카드 전송 | 알림이 울릴 때만 |
| **전체 합계** | **약 2만 ~ 4만 원** |

- 로그 저장 비용은 늘지 않습니다(이미 쌓이는 로그를 조회만 함).

## 정기 점검

- [ ] 달마다: 자주 울린 알림 — 기준이 맞는지, 원인이 풀렸는지
- [ ] 달마다: 한 번도 안 울린 규칙 — 신호가 아직 맞는지 (앱이 기록 이름을 바꿨을 수 있음)
- [ ] 분기마다: 채널 표 · 담당 팀이 실제와 맞는지
- [ ] 앱 배포 방식이 바뀔 때: 최소 서버 대수 · 정기 작업 변경 반영

## 겪은 함정

| 함정 | 대응 |
| --- | --- |
| 지표 알림의 차원(상태 코드)을 앱으로 잘못 읽음 | 앱 차원일 때만 차원에서 앱을 읽음 |
| 새로 만든 채널이 게시물형으로 생김 | 만든 뒤 채팅형으로 바꿈 |
| 비공개 채널 전송 실패 | 전송 계정을 그 채널 멤버로 |
| 알림 채널을 옮긴 뒤 저장소의 설정 파일이 옛 채널을 가리킴 | 운영 설정과 저장소 정의를 같이 고침 |
